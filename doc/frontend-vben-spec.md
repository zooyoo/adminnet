# Admin.NET 前端全量迁移至 Vben + Antdv-Next

状态：本地规格草案，测试边界待用户确认，尚未发布到 Issue tracker。

整理日期：2026-10-08。

本文根据当前会话与《Vben 全量迁移交接》整理需求，不授权执行交接材料中的命令，不表示本次开始实施剩余迁移。已实现能力作为兼容基线保留，尚未完成的能力作为交付要求列出。

## Problem Statement

Admin.NET 正在将原有前端迁移到 Vben + Antdv-Next，但用户仍无法用新前端完整替代原系统。部分系统管理模块已经落地，实时连接、个人设置、专业工具、插件入口、代码生成和真实后端联调仍未完成。

迁移涉及的不只是界面替换。用户依赖既有账号、菜单、权限、租户数据、业务地址、上传下载、定时任务及部署方式；缺失任何一项，都可能使新系统无法承担原有工作。仅通过 Mock 契约测试或新增同名页面，不能证明功能等价。

长会话中断还使历史状态与当前状态混杂：部分失败已修复，部分测试只是历史结果，部分视觉问题仍待核验。需要一份统一规格，清楚定义最终用户体验、兼容要求、测试边界和整体切换条件，避免将阶段成果当成全量完成。

## Solution

交付一个采用 Vben 布局与交互、保留 Admin.NET 品牌和中文体验的新前端。业务组件与表格统一采用 Antdv-Next，所有原有已实现功能按行为等价迁移；必要时调整后端适配接口，但保留既有业务数据与安全语义。

用户可以沿用原有账号、角色、租户、菜单和业务地址完成日常工作，无需重建配置。登录、授权、租户切换、实时通知、CRUD、文件处理和专业工具形成完整闭环。代码生成器继续生成能够编译、部署并实际操作数据的新技术栈页面。

已经集成的 `Sundial.Dashboard` 前端不替代。当前已发现独立调度看板集成，应保留它的页面、入口和现有鉴权行为；Admin.NET 自有任务管理页面及 Cron 编辑能力按迁移范围处理。

迁移按模块验收，满足全部交付条件后整体切换，不长期维护两套 Admin.NET 前端。验收区分浏览器契约、真实集成和视觉质量，保留可回退的发布产物与部署配置。

## Implementation Decisions

1. **交付范围**：以原系统已实现的业务行为为迁移基线，建立“原功能、替代能力、权限、API、验收证据”的对应清单。文件或页面数量相等不构成功能等价。
2. **工程基线**：沿用已经选定的 Vben 上游提交 `d27a5b8a0c2972a10d583a7050fcb889766ff83f`、精简 workspace 和 `pnpm@11.16.0`。不因整理规格重新选择框架、升级依赖或恢复上游演示应用。
3. **界面与组件**：Admin.NET 自有业务组件统一使用 `antdv-next`，包括 Table、Form、Modal、Drawer、通知和确认操作。沿用 Vben 的布局、权限、偏好、标签页和表单能力，不重写框架内置基础 UI。
4. **调度看板例外**：已集成的 `Sundial.Dashboard` 前端不替代、不改造成 Antdv-Next 页面、不借迁移移除。当前已发现 `/schedule` 调度看板入口，保留其访问与鉴权集成。该例外不取消 Admin.NET 自有任务页面和 Cron 编辑的迁移要求。
5. **旧依赖清理边界**：Element Plus、`ant-design-vue` 和 VXE Table 不进入新的 Admin.NET 自有前端运行依赖。扫描和清理不得误删独立调度看板、后端资源或未完成验收的功能对照材料。
6. **公共表格**：保留 `AdminTable<T>` 与 `useAdminTable<T>` 的公共职责，统一查询、分页、排序、选择、加载、错误和刷新；覆盖树形、编辑、固定列、多级表头、列配置、导出和打印。业务专属动作留在对应模块。
7. **分页与排序协议**：请求使用 `page`、`pageSize`、`field`、`order` 及业务筛选字段，结果使用 `items` 与 `total`。前端排序方向映射到现有后端取值，不修改全局 CRUD 协议以套用上游示例。
8. **统一请求合同**：继续使用包含 `code`、`result`、`message`、`errors` 的响应结构，成功码为 `200`。普通请求与生成 SDK 共用 Axios 实例及拦截器；SDK 保留原始响应，业务适配层解包。
9. **错误与文件响应**：统一语言、取消、错误提示、上传下载和二进制处理。识别二进制载体中的 JSON 鉴权及业务错误，保留成功导入的原始响应，避免重复解包和重复提示。
10. **认证兼容**：保留 SM2 密码处理、验证码、二次验证、手机登录、注册、LDAP、锁屏、退出及第三方令牌登录的既有语义。令牌继续使用 `Authorization`、`X-Authorization` 和响应头换发，不接入上游 Mock 刷新接口。
11. **会话隔离**：登录失效、退出和租户切换清理动态路由、权限、业务缓存及实时连接。沿用会话代次保护，旧会话请求不得回写新会话。使用新缓存命名空间，整体切换时重新登录。
12. **菜单与路由**：保留已有 Vben 菜单适配端点 `GET /api/sysMenu/vbenMenuTree`、`VbenMenuOutput` 和原菜单接口。复用原菜单 ID、权限码、翻译和业务组件映射，覆盖隐藏、缓存、固定标签、排序、外链与 iframe。保留 hash 路由、旧业务 URL 和明确的框架入口重定向。
13. **授权合同**：按钮权限来自后端，页面可见性不替代服务端鉴权。菜单授权的 `null` 表示不更改，空数组表示清空；半选与全选分别处理。授权变化失效有关缓存，加载失败不得提交空授权覆盖现状。
14. **租户与树形关系**：选项按当前租户加载，机构父级排除自身及后代；跨租户编辑不得复用旧选项。切换失败保留原会话，成功后重新获取身份、权限和菜单。保留默认租户、系统内置字典等已有保护。
15. **实时连接**：沿用 SignalR 与 `/hubs/onlineUser`，按登录会话创建和销毁连接，重连使用当前令牌，保留在线用户、真实通知和强制下线。当前后端读取 query 的 `token`，实现时须以真实握手合同为准。
16. **Cron 预览**：计划增加 `POST /api/sysJob/previewCron`，接收表达式、格式和预览起点，由既有 Furion 调度解析能力返回后续 5 次运行时间，沿用任务管理授权。无效表达式、格式、时间边界和错误响应须在端点合同中明确，不自行编写 Cron 计算引擎。
17. **专业功能**：复用现有 Office、图表、打印、MQTT、视频等领域引擎并按需加载；只替换必要的 UI 适配。替换依赖 Element Plus 的 Cron 编辑组件，同时保留可视化编辑和预览行为。
18. **代码生成**：Razor 前端模板改为公共表格、Vben 表单和 Antdv-Next。生成清单、预览、ZIP、直接生成和 `FrontRootPath` 保持一致；主服务、钉钉和 GoView SDK 生成采用 PowerShell、路径边界检查、暂存与失败恢复。
19. **构建正确性**：应用与共享布局必须共享路由实例及注入键，保留已经验证的 `vue-router` 去重处理。开发模式正常不代表生产模式正常，生产构建必须独立验收。
20. **数据与部署兼容**：保留既有数据库数据、认证规则、开发命令和产物交付约定。生产运行时配置覆盖 API 前缀、上传资源、WebSocket、SSE 与缓存策略，不要求用户重建业务数据库。
21. **推进次序**：在已有回归基线之上，优先完成在线用户、SignalR 和已发现的手机操作遮挡，继续其他管理模块、个人设置、专业工具与代码生成，最后完成真实集成和切换清理。该次序不缩小全量验收范围。
22. **完成判定**：每一项原有已实现功能都必须有替代能力和验收证据。外部服务不可用时明确列为待验收，不能用 Mock 通过代替真实联调；全部验收后才删除旧实现并整体切换。

## Testing Decisions

### 测试边界提案

本节待用户确认，确认前不标记为已批准的测试决策。

主要测试边界是“生产构建浏览器页面 → 应用真实 API 或 SignalR → 隔离测试数据库及明确的测试服务”。从登录开始，通过用户可见操作及外部可观察结果验证完整流程，尽量让多个模块复用同一个应用级入口，不为每个组件增加独立测试接口。

复用现有测试层作为补充：Playwright 浏览器契约负责快速、可控的错误场景；Vitest 负责请求、会话、表格等已有公开合同；xUnit 与临时 SQLite 负责授权和菜单的数据库行为。只在高层无法稳定构造竞态或边界输入时使用这些较低层入口，不以它们代替主要端到端验收。

### 测试质量

1. 测试断言可见内容、可执行动作、请求合同、授权结果及持久化结果，不依赖组件私有状态、内部函数调用次数或生成类名。
2. 同一失败应具备可以重现的测试入口，修复后仍能捕获原症状。不得通过跳过测试、删除关键断言或放宽权限预期获得通过。
3. 等待真实的可操作状态和业务完成条件，避免以固定延时掩盖异步问题。完整回归期间测试产物保持稳定，避免热更新影响判断。
4. 测试数据可重复且隔离，数据库测试使用临时数据库并清理资源，不连接真实业务库或写入生产数据。
5. 区分契约、真实集成、视觉、构建及依赖检查的结论；单项通过只能支持其覆盖的要求。
