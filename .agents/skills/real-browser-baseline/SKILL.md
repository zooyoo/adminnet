# 真实浏览器验收脚本

将一次真实用户流程写成可重复、可诊断、可清理的验收脚本。优先复用仓库当前基础设施，按用户当前要求选择设备、环境与验收范围。

## 使用前

1. 读取当前任务验收清单、最近交接记录和适用的 `AGENTS.md`。
2. 检查工作区已有改动；记录并保留与本次任务无关的文件。
3. 确认当前安装版本、构建产物和目标 API。组件 API 或 DOM 有疑问时，按仓库要求查询对应版本资料；不能套用旧版组件库的类名。
4. 区分三个边界：生产页面与 Mock API 的契约、生产页面与真实服务的集成、稳定截图的视觉验收。分别记录，不互相替代。
5. 当前仓库仅验收桌面端；以后用户调整时以新要求为准。不要从旧脚本复制手机执行路径。

首次使用向用户说明正在应用本 Skill。它不授予生产发布、真实支付、外部消息发送或破坏无关数据的权限，也不增加普通隔离测试的确认流程。

## 编写顺序

### 1. 确认隔离目标

- 从脚本位置解析仓库根目录，避免依赖启动命令的当前目录。
- 校验运行目录真实路径、允许的父目录、目录标识及 marker 内容。缺失或不匹配时立即停止。
- 本仓库复用 `start-isolated-api.ps1`、`stop-isolated-api.ps1` 和 `production-proxy.mjs`；运行目录不写死为某次历史路径。
- 代理只指向已校验的本地隔离 API，页面使用本次 `Web/dist`。不得因端口相同就认定为同一个服务。
- 停止进程使用现有路径、PID、启动时间验证。不得终止用户的开发/调试服务以解决构建锁定。
- PowerShell 命令使用 `pwsh`，脚本首部设置 `$ErrorActionPreference = 'Stop'`；原生命令之后检查退出码。文件读写显式指定 UTF-8。

### 2. 建立可靠 fixture

- 测试实体使用唯一前缀，并逐项登记已成功创建的实体和 ID。
- 先查看真实接口返回值。新增接口可能返回 ID、对象或空结果；空结果需要按唯一键查询确认，不能把 `undefined` 当成 ID。
- 业务写入优先走真实 API；通过只读数据库连接核对数据，不用直接改库替代被验收的操作。
- 测试前提显式断言：租户、角色、机构、职位、权限和外部服务是否存在。缺少前提与业务失败分开报告。
- 授权边界测试先确认操作者持有端点权限，再测试目标越权；否则只能证明端点被拒绝。
- 敏感值只在内存中使用，不打印密码、令牌、验证码、完整认证响应或连接字符串。

### 3. 先打通最小真实流程

先验证登录 → 打开目标页面 → 一次保存 → 真实响应 → 持久化结果，再扩展编辑、删除、授权和失败场景。复用已通过的 helper，但先检查其 API、设备和清理假设。

- 使用标签、角色、可访问名称和稳定业务 ID 定位；同名按钮先限定所属对话框或数据行。
- 用请求方法、精确路径及必要的业务 ID 区分响应，防止误捕获后台轮询。
- 等待响应必须先于触发动作注册；用 `Promise.all` 同时等待动作和响应，避免点击之后才订阅。
- 同时验证 HTTP 状态和业务码。HTTP 200 不一定是业务成功；HTTP 502 不一定返回 JSON。
- 保存成功后检查对话框、列表和数据库；失败后检查草稿、按钮恢复以及没有新增或篡改数据。
- 不把页面按钮隐藏当成服务端鉴权证明，不把 DTO 正确当成浏览器交互通过。

### 4. 根据真实状态等待

- 优先等待元素可见/可用、加载消失、请求返回、数据库条件或业务事件。不要依赖固定等待来掩盖竞态。
- SignalR 客户端 `start()` 返回后，服务端连接登记可能尚未完成。先确认真实在线记录，再触发依赖该连接的操作。
- 事件监听在触发之前注册；事件等待有截止时间，`finally` 清理计时器、监听和连接，避免未处理的 Promise 拒绝。
- 检查会话变化、组件卸载和迟到请求；必要时覆盖表单异步校验期间切换身份、保存期间关闭、旧密码重置结果迟到。
- 辅助失败处理采用短超时。不存在的登录密码框不应令每次失败额外等待完整默认超时。

### 5. 定位失败先观察

第一次定位失败就获取最小 DOM 证据，再决定修改；不要连续猜测选择器和重跑整个流程。

- 记录候选数量、可见性、元素类型、角色、可访问名称、所属容器和必要的类名。
- 不输出整个页面、输入值或未经脱敏的 `outerHTML`。
- 图标、中文双字间距可能改变按钮可访问名称；先查看实际名称，再决定精确匹配或限定范围。
- Select/TreeSelect 的旧浮层可能在关闭动画中仍可见。等待上一浮层完全关闭，再打开下一控件。
- `aria-controls` 不保证可见选项是目标节点的后代；虚拟列表可能另有 DOM 结构，必须现场确认。
- 虚拟列表未渲染的选项应通过真实搜索或滚动出现，再点击；不通过直接调用应用函数绕过用户操作。
- CSS 定位是版本相关的后备方案；记录验证版本和结构依据。禁止用无理由的 `.first()` / `.last()` 消除歧义。

本仓库已经验证的案例见 [定位与失败经验](references/lessons.md)。

### 6. 产出可复核证据

- 报告初始化为失败，记录阶段、通过步骤、失败步骤、验收边界和产物位置。全部断言通过后才设置 `passed: true`。
- 功能通过与清理通过分开记录，例如 `passed`、`cleanupPassed`；单一脚本不得擅自关闭完整提案。
- 覆盖初始化失败：资源创建也放在可记录错误并释放已创建资源的控制范围内。
- 先保存脱敏失败报告，再尝试截图和清理；后续错误不能覆盖最初失败。清理结束后补写最终清理结果。
- 成功截图等待通知、动画、加载和临时浮层结束，确认正确标签页。必要时还原表格横向滚动和正文滚动位置。
- 错误态截图保留真实错误提示，确保草稿和关键按钮可见；不得用错误态截图代替成功态视觉验收。
- 真实查看截图，检查内容、遮挡、裁切、滚动和按钮可达性；“截图文件存在”不等于视觉通过。
- 密码重置等敏感弹窗必须先关闭或可靠遮罩再截图。未能确认脱敏时，跳过截图并记录原因。

### 7. 清理与结束

- 按依赖顺序删除自己创建的关联和实体，逐项尝试；某一清理失败不能阻止其他清理。
- 同时保存主失败和清理失败，不能以清理异常替换业务失败。
- 清理后核对记录确实不存在；只声明实际检查过的数据已清理。
- 停机测试放在最后：先准备页面草稿、完成其他验收和必要清理，再停止经过校验的隔离服务。
- 真正请求停止后的服务并验证失败状态、草稿和无写入；不得通过 `page.route` 伪造失败来关闭真实停机验收。
- 无论成功失败，释放浏览器 context、browser、代理、WebSocket、请求、只读数据库连接；释放失败也应报告。
- 停止服务和删除运行目录是两件事。按任务要求保留数据库与证据，不自动删除失败现场。

## 验证与提交

- `.mjs` 修改先做 `node --check`；业务代码变化执行对应 lint、类型、相关测试与构建。
- 使用最终构建验证受影响真实流程。只有代码变化、失败或未解决的问题才需要重复或扩大验证。
- Mock 契约默认拒绝未声明 API 请求，避免误访问开发后端；报告显式标记 Mock 边界。
- 记录工具限制与既有告警。工具只回显参数或退出码为 0，不足以证明检查真正执行。
- 更新任务证据、总进度和交接，再按用户授权提交相关文件；不要把整个工作区一并提交。
- 不声称使用了不可调用的上下文压缩工具；交接摘要与上下文压缩分别表述。

## 每次执行后的持续更新

每次编写、修改或执行真实浏览器验收脚本结束时：

1. 检查是否出现新的可复用经验：前提错误、返回合同、定位、异步竞态、截图、脱敏、清理或工具限制。
2. 在 `references/lessons.md` 记录日期、适用版本/条件、症状、根因、验证有效的处理及适用限制。
3. 只有已验证且通用的规则才提升到本文件；尚未验证的想法明确标为“待验证”，不写成固定要求。
4. 新证据推翻旧规则时修正旧条目，注明替代原因；不无止境追加重复建议。
5. 没有新经验时不制造 Skill 变更；在当前任务记录“已复核，无新增通用经验”即可。
6. 更新 Skill 后检查 frontmatter、相对链接、路径、脱敏和示例有效性；按当前用户授权提交，保留无关改动。

Skill 记录可复用的方法，任务 issue 记录本次结果，临时报告保存运行细节。不要将运行目录、实体 ID、账号凭据或某次失败输出固化成通用配置。
