## 1. 已确定方案

**完全自研统一单据设计工作台，采用用户已认可的新版方案 A。** 排除 pdfme，不接入成品表单／报表设计器。

目标：通过拖拽定义新单据，基于同一单据字段设计套打模板和查询报表；支持增删查改、导入导出、打印、提交、撤回、审核、反审、作废、关闭。

技术基础：Vue 3、TypeScript、Vben、antdv-next、.NET 10。优先复用仓库现有表单、列表、权限和数据访问能力。

**经典三栏布局：** 左侧字段／控件库；中间录入／套打画布；右侧“字段属性／单据配置”。顶部提供模式切换、预览和保存草稿。

字段属性：名称、示例值、列宽、必填、字段绑定。单据配置如下：

| 配置组 | 配置内容 |
| --- | --- |
| 基础信息 | 单据名称、标识、业务分类 |
| 编号规则 | 前缀、日期部分、流水号位数、编号示例 |
| 业务操作 | 各项单据操作的启用／停用 |

| 打印设置 | 默认模板、打印抬头、签字区域 |

原型为独立 HTML，仅保留内存状态，刷新恢复示例。“保存草稿”是演示标记，业务操作栏和审批设置只展示效果。

## 3. 正式实现的架构要点

以下是架构建议，尚未落地：

1. **共享字段，独立布局。** 单据定义统一字段、明细、规则和操作；录入布局与打印模板分别保存节点树，通过稳定字段 ID 绑定。一个字段可在多个位置展示，删除展示节点不等于删除字段。
2. **共享编辑内核。** 统一选择、拖拽、属性编辑、命令、撤销重做和草稿；录入使用栅格／容器策略，打印使用物理坐标／区域策略。可从录入定义生成初始套打模板，再独立调整。
3. **独立存储协议。** 单据定义采用纯数据结构，经过适配后交给 Vben 渲染。现有 Schema 含函数和组件对象，不能直接作为持久化协议。
4. **后端执行业务。** 保存、导入共用校验与写入逻辑；查询、导出、打印共用租户及数据权限。操作统一处理并发、幂等、事务和审计。审核、有效性、执行状态分别建模；反审检查下游引用和业务影响。
5. **自研打印排版。** 同时考虑固定套打与流式明细，支持毫米坐标、文本测量、重复表头、分页和汇总。授权数据集驱动输出，预览与 PDF／打印共用排版结果。
6. **版本从首版纳入。** 区分草稿、不可变发布版本和实例使用的定义版本。模板独立修订并声明兼容性；精确历史重打需保留数据快照、模板及渲染资源版本。

查询报表以单张单据、单据列表、分组汇总为数据集，复用条件表单与打印排版。存储结构、审批复杂度、打印输出技术仍待确定；“固定业务外壳＋JSONB 动态字段＋独立明细行”仅为候选存储方案。

## 4. 完成状态与未完成项

**已完成：** 新版方案 A 的交互原型；配置联动、撤销重置、字段绑定、预览和总览同步均通过浏览器检查，未捕获页面脚本错误；1024／1280／1440 像素桌面宽度无页面横向溢出。

**未完成：** Vue 应用集成、持久化与发布、真实 CRUD、导入导出、业务状态机、权限与事务验收、动态明细编辑、查询数据集、精确分页、PDF 输出和实机套打。

**原型模型不能直接用于生产：** 当前 A 使用同一份 `fields` 数组驱动录入和打印，添加／移除会同时影响两者；正式实现应拆分字段定义与两套布局节点。当前拖拽仅演示添加，尚无完整的自由定位、重排、吸附和多位置字段引用。
