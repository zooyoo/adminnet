# 领域文档约定

## 资料入口

本仓库共享前后端的领域用语和业务契约，不因 pnpm workspace 分包而自动拆成独立业务领域。探索功能时按需要阅读：

1. [项目说明](../../README.md) 与 [开发指南](../development.md)，确认当前结构和入口。
2. 目标模块的 `AGENTS.md`、`CLAUDE.md` 及实际服务、实体、DTO、权限与测试。
3. [文档索引](../README.md) 中与功能有关的协议，例如 [打印服务合同](../frontend/pdfme-print-service.md)。

根目录的 `GLOSSARY.md` 和 `docs/adr/` 是可选的未来资料位置，目前未作为必备依赖。仅在实际存在且与任务相关时读取，不创建空文件凑配置，也不因不存在阻塞工作。

## 使用约定

- 规格、任务、排错和测试命名沿用源码已确定的业务用语。新术语先核对已有名称，再记录解释，避免把临时推断写成既定事实。
- 接口、权限、租户隔离和外部服务协议发生变化时，同步更新实现、相关测试和实际存在的文档。
- 若已有架构决策与拟议方案冲突，指出对应资料和重议原因，保留必要的决策背景。
- 将长期契约放入 `docs/` 或对应模块说明；任务日志、证据截图和逐轮交接保存在临时工作区，清理前提炼仍有价值的内容。
