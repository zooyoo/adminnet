# 提案推进前的子智能体收尾

按编号执行多个提案时，在开始下一编号的分析、派发、实现之前执行本流程；恢复会话或上下文压缩后也先核对。用户明确指定联合范围时，以该范围作为当前批次。

## 推进条件

当前批次的业务验收、变更交付和子智能体关闭全部成立，才可进入下一批次。业务测试通过或提交完成只证明业务交付；`inactive` 只说明没有回合正在执行，`turn/end: completed` 只说明一次回合结束。

1. 列出当前主会话派生的全部子智能体，包括 Team 成员、普通可续聊子智能体、失败重试遗留和一次性委派；记录所属提案、ID、结果和宿主生命周期状态。复用成员时仍保留最初归属，直到完成关闭。
2. 收齐最终结果，核对未完成任务、运行中的回合、待投递消息和后台进程。失败、取消、超时逐项处理并记录，不以这些状态代替成功交付。
3. 调用宿主支持的关闭操作，然后重新查询：所有可续聊子智能体均为终态，无法再被消息唤醒；一次性委派已经结束。保留关闭回执和验收证据。
4. 运行 `node scripts/agents/check-proposal-closeout.mjs --session-file <主会话日志绝对路径> --next <下一编号>`。脚本只读宿主日志并输出脱敏检查结果；退出码 `2` 表示阻塞，`1` 表示无法核验，均须停留在当前批次。日志快照检查通过后，仍须核对宿主实时状态和业务验收，脚本不是宿主的原子调度锁。
5. 将收尾结果写入进度记录；完整记录包括：业务验收结果、子智能体清单、关闭回执、检查时间、下一编号及是否获准进入。全部通过后才派发下一提案。

## 关闭能力缺失或状态不明

把下一提案标记为“阻塞：等待子智能体关闭”，保留已完成的业务验收和未完成的代码。等待宿主提供可核验的关闭能力，再按第 3 步重新核验。

用户已明确要求：本次处置不修改本地 DSH 源码，不应用宿主补丁。修正仅限项目规则、检查脚本和进度记录；关闭能力缺失时维持阻塞，不以修改宿主绕过此边界。

当前核验的 DSH Team API 只有 `interrupt_agent`，其行为是中断回合并保留收件箱；它不是关闭。`list_agents` 的 `inactive`、异常结束、用户取消、新开会话、达到成员上限后复用旧成员，都不能替代关闭回执。不得通过编辑会话日志、删除历史、手写“已关闭”状态或绕过模型拒绝来通过门禁。

宿主已有 `workspace/archiveSession({ sessionId, stopActivity: true })` 能力：持久归档并请求停止当前工作；归档运行门槛阻止该会话及其子智能体后代再次执行模型步骤，直到明确取消归档。可通过已登录界面或已获授权的宿主管理接口调用，不需要修改 DSH 源码。操作后须回查归档集合并确认运行已结束；归档回执本身不等待所有活动结束。归档不等于从 Team 历史名册退休，也不保证释放 8 人名额。

## 已归档会话的核验

宿主已归档但历史日志没有关闭事件时，在第 4 步追加 `--host-url http://127.0.0.1:19387`（使用当前 DSH 实际地址）。脚本直接读取 `/api/dsh-session-archive/inventory`，要求清单在 60 秒内、ID 规范化后无重复、父子归属匹配、权威 `archivedSessionIds` 包含成员，且成员 `archived=true`、`running=false`。该参数只执行读取；不接受手写清单文件作为宿主回执。

- 未传宿主地址时仍只回放旧日志；其缺回执结果不能证明用户归档失败，也不会因等待而自动同步。
- 宿主额外侧会话及后代记录为 `HOST_CHILD_NOT_IN_LOG`，需读取其日志并区分继承历史与新增调用，不能忽略或重复计算继承的委派。
- `UNSETTLED_RESULT` 表示失败、中止或仍运行的回合。对已归档且停止的失败实例，核对其写入范围、接手人、后续提交和原始验收报告，保留原始结果及处置证据；归档不会自动让业务验收通过。
- 仍运行、待投递消息、未知归属或缺失证据时保持阻塞；业务处置不能替代归档回执。
- 对直接继承主会话、末次 completed、没有待投递消息或新增委派、唯一新增工具类型为 ctx_stats 的已停止归档侧会话，脚本可通过日志内容比较识别 inheritedReadOnly；其他额外实例仍需核对。

完成失败任务的逐项交付核对后，可在 `--host-url` 后追加 `--review-file <业务处置 JSON>`。处置必须匹配会话、下一编号和原始日志 SHA-256 摘要，并包含每条失败记录的原始 outcome、所属提案、原因及证据文件 SHA-256。先前任务的接手交付要求原始报告 passed=true、cleanupPassed=true、cleanupErrors=[]；当前提案 aborted 只能记录为 resume-current-proposal，仍需随后完成实现验收。所有处置都要求当前宿主归档且停止，原始 outcome 保留，消息和运行阻塞保持生效。通过状态为 reviewed-clear，退出码 0；这表示收尾核验通过，不表示下一提案已完成。证据变动须重新核对，不通过更新摘要盲目接受变更。

2026-10-11 已通过上述宿主接口成功归档遗漏的 11 个子会话，并回查 18 个直接子会话已归档且停止。历史 RPC 根入口的 HTTP 401 不代表这个插件接口不可用。具体业务处置见 `.scratch/proposal-agent-lifecycle/closeout-reconciliation.md`；不需要重新唤醒超长旧会话来执行归档。
